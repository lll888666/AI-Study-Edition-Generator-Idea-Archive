02

缘起与问题

Origin of the Idea

这个项目的出发点不是「做一个更漂亮的 PDF 阅读器」，而是解决一个真实存在的学习摩擦。

§01 · ORIGIN OF THE IDEA

资料太多，但吸收效率太低Too much material, too little absorption

大学阶段可能同时面对 Machine Learning、Operating Systems、概率论与数理统计、离散数学、Computer Vision、数据结构、商务英语、CET-6、雅思、各类竞赛、AI Salon、Vibe Coding 与各种线下活动——传统课堂效率有限，单纯读教材容易疲劳，而每遇到不懂的地方都复制粘贴去问 AI，学习流程非常割裂。

Machine Learning Operating Systems 概率论与数理统计 离散数学 Computer Vision 数据结构 商务英语 CET-6 雅思 竞赛 AI Salon Vibe Coding

真正的问题不是「没有资料」，而是「资料太多，但吸收效率太低」——THE REAL PROBLEM IS NOT LACK OF MATERIALS, BUT LOW ABSORPTION EFFICIENCY

《教材帮》在做什么

中学教辅不会把课本重新打印一遍，而是：

  • 拆知识点、划重点、标难点
  • 提醒易错点、给出例题
  • 总结方法、加知识图谱
  • 用更容易理解的语言解释

传统教辅背后的团队

一套教辅需要大量人力共同完成：

  • 高级教师 · 学科专家
  • 命题研究人员 · 内容编辑
  • 审校人员 · 美术编辑 · 排版人员

核心想法：能不能把这条传统教辅生产流程逐步 AI 化？最终做到 —— 上传一本电子教材，AI 自动生成一份真正具有教学价值、考试价值和交互能力的数字教辅。

§02 · PRODUCT DEFINITION

产品定义：数字教辅生成器Digital Auxiliary Textbook Generator

产品暂定名 AI Study Edition Generator，一句话定义：将普通电子教材自动转换为具有重点标注、大白话解释、易错提醒、知识结构、专业审校和互动练习能力的数字教辅。

英文宣传语 "Turn any textbook into an interactive AI study guide." // 更完整： "Transform static textbooks into structured, explainable, interactive and executable learning environments."
03

核心问题 · 最重要原则 · 三种模式

Core Problem · The Principle · Two Modes + One Long-term

真正难的从来不是生成文字，而是教学判断。先立原则，再谈产品形态。

§03 · CORE PROBLEM

AI 总结 ≠ 教辅Summarization is not a study guide

很多 AI 学习工具只是「上传 PDF → 总结 → 问答 → Flashcards」，而真正的教辅需要一条完整的知识加工链。

大多数工具在做

  • 上传 PDF
  • AI 总结
  • 问答
  • Flashcards

真正的教辅需要

  • 原教材 → 知识拆解 → 教学重组
  • 重难点判断 · 易错点分析
  • 例题设计 · 方法总结
  • 内容审校 · 版式设计

真正难的不是生成文字，而是 Pedagogical Judgment —— 教学判断—— 什么该解释、什么该高亮、哪里容易误解、应该给什么例子

§04 · MOST IMPORTANT PRINCIPLE

最重要原则：内容质量第一Content quality above all features

这个项目最重要的不是功能丰富，也不是页面好看，而是专业准确性 > 教学价值 > 证据可靠性 > 阅读效率 > 视觉设计 > 交互功能。如果重点划错了、易错点是 AI 编的、公式解释错了，那么 SVG、动画、Jupyter、视频和漂亮 UI 全部没有意义。

§05–07 · THREE MODES

三种产品模式Mode A · Mode B · Long-term Mode C

第一阶段是「学霸批注版」，第二阶段是「前置大白话版」，长期目标是「完整教辅版」。切换标签查看每一种形态 —— Mode A 里还内置了一段可交互的批注演示。

原则：原文不改，只增加一层 AI 学霸批注层。效果应该像——一本已经被「学霸认真做过笔记」的电子教材。

Original Textbook（原教材） + Annotation Layer（批注层） // 黄=核心定义 · 红=常见错误 · 蓝=大白话 · 绿=直觉类比 · 紫=前置知识
批注开关：
梯度下降（Gradient Descent）是一种通过迭代更新参数、使目标函数逐步达到最小值的优化算法。 其核心思想是：沿损失函数的负梯度方向移动参数，使损失值逐步下降。 更新公式为 w ← w − η·∇L(w)，其中 η 为学习率。 需要特别注意：梯度本身并不是参数的实际更新量， 实际更新还需要乘上学习率。 （直觉：想象沿山路下山）
▲ 点击或悬停任意高亮文本，查看对应批注内容（红字为易错点）。

第二条产品线：不是在原教材上批注，而是重新生成一本「读原教材之前先看的前置教材」——读完以后再回到专业教材，明显更容易理解。

内容特点

  • 语言更简单，专业术语保留
  • 公式减少但不删除
  • 大量直觉解释与生活类比
  • 减少实现细节，强调知识框架

风格参考

  • 「10 分钟搞懂……」
  • 「从 0 到 1……」
  • 「原来……这么简单」

但不能沦为浅薄科普——它仍然必须为专业教材服务。

未来真正的目标：把原教材重新组织成完整教辅，结构类似传统高质量教辅 —— 这一步才真正接近「AI 自动制作《教材帮》式教辅」。

Chapter Overview（章节总览） Knowledge Point 1（知识点 1） ├─ 定义 ├─ 大白话 ├─ 重点 ├─ 难点 ├─ 易错 ├─ 例题 ├─ 解题方法 └─ 练习 Knowledge Point 2 … Chapter Mind Map（章节脑图） Chapter Summary（章节总结） Chapter Quiz（章节练习）
04

为什么主格式是 HTML

Why HTML Should Be the Main Format

不是 PDF，也不是 DOCX。HTML 是唯一能同时承载排版、矢量图、数学公式、代码运行与交互测验的格式。

§08 · WHY HTML

HTML 是主格式，PDF / DOCX 只做次级导出HTML first · PDF / DOCX as secondary export

HTML 能做什么

响应式布局 CSS Grid 排版 SVG 矢量图 Mermaid 流程图 Markmap 思维导图 KaTeX 数学公式 动画 视频嵌入 Monaco 代码编辑器 JupyterLite 终端 测验 AI Tutor

为什么不是 PDF / DOCX

PDF / DOCX 只能静态阅读，无法内嵌可运行的代码、交互测验与知识图谱。它们更适合打印与线下分发，作为 secondary export（次级导出格式）保留即可。

§09 · DIGITAL-NATIVE ADVANTAGE

数字教辅真正的优势：可执行教材Executable Textbook

传统纸质教辅只能「看 → 理解 → 自己另找地方练」；数字教辅可以做到「阅读 → 理解 → 尝试 → 运行 → 反馈」。例如 Python 教材，正文代码下方直接出现运行按钮，用户可以修改并执行。

R01Read 阅读→ R02Understand 理解→ R03Try 尝试→ R04Run 运行→ R05Feedback 反馈 
for i in range(10):
    print(i)
▶ 运行 Run 

        

        
未来可嵌入：Monaco Editor（VS Code 风格）· JupyterLite（浏览器 Notebook）· Pyodide（浏览器 Python）· Remote Kernel · Terminal —— 于是电子教材变成 Executable Textbook（可执行教材）。

点击任意环节，查看 Agent 的职责8-stage editorial line · interactive

        

          

            

            
01
Source Parser · 教材解析
解析 PDF / EPUB，识别章节结构、公式、代码、图表与图片。

Content Analyst · 内容分析

§19 · TEACHING SKILLS

      

        
教师专家 Skill：蒸馏上百万分钟的真实教学Distillation of teaching styles

        
把高级教师、大学教授、命题专家和高质量教辅作者的教学材料进行 distillation（蒸馏），生成面向不同课程的教学 Skill。Skill 负责「教学方法和组织方式」，不是直接代替事实来源。

        

          
Professor Style Skill
教授视野：先直觉后严格，强调动机与历史脉络。

          
Exam-oriented Skill
应试视角：直奔考点、题型与得分点。

          
Beginner Explanation Skill
零基础友好：先大白话，再上术语。

          
Proof-focused Skill
证明导向：条件、引理、推导链清晰。

          
Code-focused Skill
代码优先：signature、语义、边界条件全覆盖。

          
Routing Rule
不同课程调用不同 Skill，按学科画像自动选择。

    §25 · DEV PHILOSOPHY
    
      
    
        
    开发哲学：小闭环，而不是大爆炸Small Loop Development
    
        
    不要一次让 Agent 开发「PDF Parser + OCR + RAG + Monaco + Jupyter + SVG + 视频 + AI 图片 + App + Cloud」。而是：第一章 → 批注 → HTML → 真实使用 → 改，然后一次只加一个 Skill 或一个功能，重新测试。
    
        
    
          
        
    
      
    
    
    

    
    
      
    §26 · STAGE ROADMAP
    
      
    
        
    完整路线：Stage 0 → Stage 1011 stages · click to expand
    
        
    从「第一章 HTML 批注 Demo」到「个性化 AI 教辅」，每一阶段都建立在上一个阶段的真实使用反馈之上。
    
        
    
          
    STAGE 0第一章 HTML 批注 Demo 当前
    选定一本书的第一章，产出批注版 HTML。先真实使用，满足成功标准再继续。
    
          
    STAGE 1整本教材批注
    把批注流程扩展到整本教材，完善锚点定位与批注密度控制。
    
          
    STAGE 2大白话前置教材
    生成「读原教材之前先看的前置教材」，让回读专业教材变得容易。
    
          
    STAGE 3教辅式结构重排
    章节总览 → 知识点 → 例题 → 练习 → 章节脑图 → 测验，向 Mode C 靠近。
    
          
    STAGE 4学科 Profile
    为不同课程配置关注维度：ML 看张量形状，OS 看状态转换，概率看条件与推导……
    
          
    STAGE 5教学专家 Skill
    蒸馏名师教学材料为可调用 Skill，按学科画像自动路由。
    
          
    STAGE 6证据检索 + 多 Agent 审校
    接入课程大纲、历年试题等真实证据源；Reviewer 与 Critic 制衡生产。
    
          
    STAGE 7Notebook / Monaco / Terminal
    代码可改、可跑、可反馈 —— 真正变成 Executable Textbook。
    
          
    STAGE 8视频片段 / SVG / 动画 / 思维导图
    每个知识点绑定图、导图、知识片段与动画。
    
          
    STAGE 9多教材通用
    适配不同教材源、不同语言、不同学科的通用流水线。
    
          
    STAGE 10个性化 Personalized
    根据学生水平、考试目标、剩余时间、薄弱知识与学习记录，自动调整批注密度、解释深度、题目难度与知识顺序。

    §28 · CORE INNOVATION
    
      
    
        
    真正的创新点：四个不可替代的引擎PDF parsing / HTML / RAG / LLM 都已存在 —— 核心资产是这四件事
    
        
    
          
    ENGINE 01
    Pedagogy Engine 教学编排引擎
    决定：什么该解释、什么该高亮、哪里容易误解、应该给什么例子、如何组织顺序。
    
          
    ENGINE 02
    Evidence Engine 证据引擎
    决定：为什么这是重点、为什么这是易错、依据来自哪里、置信度是多少。
    
          
    ENGINE 03
    Study Guide Schema 教辅结构协议
    决定：AI 输出什么结构化内容 —— 所有 provider 与前端之间的契约。
    
          
    ENGINE 04
    Design System 数字教辅设计系统
    决定：如何稳定地把同一份数据变成高质量的教辅页面，而非千篇一律的 AI 排版。
    
        
    
      
    
    
    

    
    
      
    §29 · MAIN LIMITATION
    
      
    
        
    核心局限：最难的不是技术，而是教学判断Known limitations & guardrails
    
        
    
          
    
          
    教学判断可靠性
    AI 是否真的知道：什么重要、什么难、什么容易错、什么值得考、什么解释更好。这是项目最需要长期打磨的问题。
    
        
    
        
    
          
    
          
    学科适配 · 参考资料质量 · 版权
    不同课程无法完全统一：垃圾来源会导致错误结论；公开产品不能随意公开完整商业教材 —— 每一关都需要设计与约束。
    
        
    
        
    
          
    
          
    AI 过度生成 Over-generation
    很容易变成「每一句话都批注、每一个概念都解释」的信息过载。因此必须设计 Annotation Density Control（批注密度控制），让批注密度可调。
    
        
    
      
    
    
    

    
    
      
    §30 · FINAL PHILOSOPHY
    
      
    
        
    最终理念：减少理解教材过程中的不必要摩擦Drag the handle · 拖动滑杆对比学习流程
    
        
    这个项目不是让 AI 替学生学习，而是把「看不懂 → 复制 → 打开 AI → 问 → 理解 → 回来」压缩成「读教材 → 旁边已经有解释 → 继续读」。所有学习资源围绕教材本身组织，而不是散落在十几个 App 里。
